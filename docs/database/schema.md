# Database Foundation Schema

## Conventions

- PostgreSQL 15 is the supported local database baseline.
- Primary keys use UUID values generated by PostgreSQL.
- Event timestamps use `timestamptz`; business validity dates use `date`.
- Email uses `citext` and is unique without regard to case.
- IP addresses use `inet`.
- Authentication tokens and refresh tokens store hashes only.
- Status-like values have database `CHECK` constraints.
- Foreign keys use explicit delete behavior.
- Migrations are mandatory; production schemas must not be edited manually.

RLS is intentionally deferred until the tenant schema is stable. Tenant-owned roots introduced in later phases must expose `UNIQUE (organization_id, id)`, and important children must carry `organization_id` with composite foreign keys. `organization_member_roles` already demonstrates this pattern and cannot point to a member of a different organization.

## Implemented modules

### Identity

- `users`
- `user_credentials` — optional one-to-one local credential, allowing future SSO-only users
- `email_verification_tokens`
- `password_reset_tokens`
- `user_sessions` — revocable sessions with hashed refresh tokens

### Organization and system RBAC

- `organizations`
- `organization_members`
- `roles`
- `permissions`
- `role_permissions`
- `organization_member_roles` — multiple roles per member

Roles are system-defined in this phase. Tenant-defined custom roles are not supported.

### Reference geography

- `countries`
- `markets`

Seeds include Vietnam, China, and `CN_GACC`.

### Product foundation

- `products`
- `product_varieties`
- `product_forms`

Seeds include durian and the forms `FRESH`, `FROZEN_WHOLE`, `FROZEN_PULP`, and `FROZEN_PUREE`.

### HS foundation

- `hs_nomenclatures`
- `hs_codes`
- `product_hs_codes`

HS code uniqueness is scoped to a nomenclature. Product mapping supports optional product form, market, and validity dates. No HS code is seeded because no official classification source was supplied and verified for this phase.

## Seed strategy

Reference seeds use natural codes as conflict targets and either update descriptive fields or ignore an existing relationship. Re-running the migration runner skips recorded migrations; executing the seed SQL itself again is also idempotent. Seed data is operational/reference data only and contains no MRL or legal conclusion.

## Deferred explicitly

Export batches, facilities/PUC/PHC, documents, OCR, measurement units, legal knowledge, RAG, rule execution, AI, findings, reports, remediation, monitoring, alerts, dashboards, and RLS policies are outside Foundation Phase 01.
